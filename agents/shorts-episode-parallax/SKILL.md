# Shorts Episode Prompt — 2.5D Parallax Explainer

Turns an everyday "why does this happen?" question into a ready-to-use episode file for a faceless Shorts series drawn in a bright, friendly 2.5D parallax style, plus the title, description and hashtags to publish it. The file is pasted into Codex, which builds the scenes in Remotion; the voice-over is pasted into ElevenLabs.

This skill is a sibling of `shorts-episode-prompt`. The pipeline, voice-over timing, accuracy discipline and file structure are the same. What changes is the look (bright, layered, characters allowed instead of dark UI), the story shape (an everyday question with a relatable character) and a new set of rules that keep episodes from looking mass-produced.

## The user's pipeline (assume this unless told otherwise)

- Faceless Shorts for YouTube and TikTok, 9:16, about 42-50 seconds (the layered scenes need a little more room than the 37-40 seconds of the Mystery series).
- Scenes are generated by Codex with Remotion. Voice-over is generated by Workflow Studio through the ElevenLabs API after creator approval.
- Series (playlist): **Everyday Why** is the working name. If the user names it differently, use their name everywhere. It lives on the same channel as the Mystery series but is its own playlist with its own numbering (#01, #02, ...). Tell the user in one line when you use the working name, so they can rename it.
- Voice-over and on-screen captions are in **English**. The user chats in Indonesian, so reply in the language they write in, but write the episode file in English. If the user asks for Indonesian on-screen text (as in the Internet Mysteries series), keep the narration in English and put only the on-screen text in Indonesian.
- The look is drawn entirely with code (SVG shapes, CSS gradients, Remotion transforms). No photos, stock footage, or generated images. See `references/style-bible.md`.
- `references/market-research.md` explains why this style and format were chosen. Read it when the user asks about strategy, monetization, topics, or "is this worth it".

## Workflow

1. **Pin down the inputs.** Topic, series name, episode number. If an earlier episode of this series exists in the conversation or was uploaded, read it and match its constants and reusable components. If something can be inferred, infer it. Ask at most one question, and only when the topic itself is missing. If the user wants ideas rather than a script, switch to ideas mode (below).

2. **Verify the facts.** Everyday-science content gets corrected in the comments just like mystery content. Use web search for any claim about animals, the body, nature, history, or numbers, and prefer primary or institutional sources (zoo, museum, university, agency, journal). Name the sources in the accuracy note. Anything you cannot verify is dropped or labeled as a simplified illustration.

3. **Shape one question into a story.** One idea per episode. Default arc: hook question, setup (a relatable moment with the character), mechanism (the visual explanation), the surprising fact (the one bold moment), cost or counterpoint, twist line, end card. See "Story rules".

4. **Decide what changes since the last episode.** Fill the "Variation vs previous episode" line (see "Originality and variation"). Do this before writing scenes, because setting, palette family, character and camera move are chosen here.

5. **Write the voice-over first, then the scenes.** The narration sets the timing. Scene prompts, durations and camera keyframes follow from it. See "Voice-over rules" and "Scene prompt rules".

6. **Write the file** using `references/episode-template.md`. `references/example-everyday-why-01-flamingo.md` is a finished episode that shows the expected level of detail and tone.

7. **Deliver.** Follow the episode AGENTS.md output contract: save the complete package as `01-episode.md` in the current episode directory, with the exact `## Master Voice-over` fenced-text section requested by the app. In the chat reply, give a short summary: the arc in a few lines, the main accuracy choices, approximate duration, the "Variation vs previous episode" line, and one suggested next step. Do not paste the whole file into the chat.

8. **Publish pack.** When the user asks for a title, description or hashtags (or after delivering the file, offer it in one line), follow `references/publish-pack.md`. Keep it in the chat unless the user asks for a file.

## Story rules

- **Hook (first 3-5 seconds):** an everyday question or a claim that creates a gap ("Every flamingo is born gray. So where does the pink come from?"). It must be true and must pay off within the video. The first frame already shows the character or the subject, not a title card.
- **One surprising thing.** Pick the single fact or contrast that makes someone say "wait, really?" and build everything toward it. Cut anything that does not serve it.
- **A relatable anchor.** Start from something the viewer has seen or done (a color, a taste, a habit), then reveal the mechanism behind it. This is what makes the style feel like a friendly explainer and not a lecture.
- **Twist line:** one short sentence that reframes what came before. It becomes the end card text, so write it so it works as a title card.
- **Tone:** warm, curious, a little playful. Wonder comes from the idea, not from exaggeration. No fear-mongering, no "scientists are shocked".
- **Balance:** where a claim has a fair counterpoint ("usually X, but not always"), include it in one short line.
- **Series links:** where natural, connect to an earlier episode (a reused character, a shared concept) and tease the next with "Follow for #NN". Connections are optional here; variation matters more than continuity.

## Voice-over rules

- Plan for about 2.2-2.5 spoken words per second, including pauses. For 42-50 seconds with a silent end card, that is roughly 95-110 words. State the word count and estimated duration in the file.
- Short sentences. One idea per line. Use "..." for a deliberate pause and blank lines between beats; ElevenLabs reads these as pauses.
- Write numbers and symbols the way they should be spoken. Keep symbols and abbreviations for on-screen text.
- No stage directions, scene labels, or emojis inside the narration block. The "Full voice-over" section must be paste-ready.
- The end card usually has no voice-over.
- Vary the sentence rhythm and the hook formula from episode to episode (see below). Identical narration scaffolding across episodes is one of the clearest signs of a template.

## Scene prompt rules

Each scene has: a title, suggested duration, purpose, a Codex prompt in a `text` code block, and its voice-over lines. Scenes that move the camera also list their camera keyframes in the Camera Plan section of the file.

A good Codex prompt:
- Opens with the format: "Create a vertical 9:16 2.5D parallax flat-vector animation scene for a faceless YouTube Short, in a warm, friendly explainer style."
- After Scene 01, states continuity: "Continue the exact same visual identity, characters and palette as the previous scene."
- Describes the scene **back to front**, layer by layer (sky, far scenery, mid scenery, subject plane, near props, foreground), using the depth numbers from the episode's Layer Map. Say which layers are blurred and which one is in focus.
- Describes the **camera move** in plain words (slow push-in, pull-back reveal, tilt-up, lateral drift, rack focus) and how far it travels.
- Describes character action concretely (what the character holds, looks at, does, and when they blink or react), and any idle motion (breathing bob, swaying plants).
- Puts all on-screen text in quotes exactly as it should read.
- Names the mood in one line (warm and curious, not dramatic).
- Ends with the standing exclusions: no real people, no real brand logos or interfaces, no existing cartoon characters or channel mascots, no photos or generated images (everything drawn with code), no heavy outlines, no scary or graphic imagery, key content inside the mobile safe area, 9:16 vertical.
- Stays code-drawable. Characters are built from simple shapes (circles, rounded rectangles, capsules); see the character spec in `references/style-bible.md`.

Rules across the whole episode:
- **Spend visual boldness on exactly one moment** (the surprising fact, usually a pull-back reveal, a color change, or a light burst) and keep every other scene calm. Name that moment in the "Component Design" section.
- **Keep the series constants fixed** and change only the episode variables (see "Originality and variation").
- **Cap the technical load.** At most about 8 layers per scene and at most 3 blurred layers on screen at once, because blurred full-screen layers are the slowest thing to render in Remotion. Say so in the Remotion note.
- Include the **Component Design** paragraph pointing Codex to the bundled style-bible.md for UI pieces (info card, labels, diagram arrows, caption pills), so they feel specific to the story rather than templated. If the user asks for /top-design, point to that instead.

## Originality and variation

This is the part that the dark Mystery series did not need and this series does. YouTube's monetization policy treats template-driven videos with little variation, and generic AI content without the creator's own insight, as "inauthentic". A synthetic voice reading an original script is not the issue; sameness at scale is. The details are in `references/market-research.md`.

**Series constants (never change between episodes):**
- Flat vector look with no outlines, soft elliptical ground shadows, subtle paper grain
- One rounded sans-serif typeface family and the caption style
- The info-card style
- The end-card layout (twist line over a sunburst gradient, series name, episode number, "Follow for #NN")
- The standing exclusions

**Episode variables (must differ from the previous episode):**
- Setting and palette family (for example lagoon sunrise, kitchen interior, night sky, desert noon)
- Main character: silhouette, hat or hair, outfit colors, and role
- Hook formula (question, "everyone knows X but...", "nobody tells you...", a number, a what-if)
- Primary camera move (pull-back, tilt-up, lateral drift, push-in, rack focus)
- Type of bold moment (reveal, color change, scale jump, light burst)
- Narration scaffolding (do not reuse the same sentence frame for the setup and the takeaway)

Write one "Variation vs previous episode" line in the file listing what changed. For episode #01, write "First episode of the series; this sets the constants."

Also add original insight in every episode: a concrete detail, a counterpoint, or a connection the viewer is unlikely to have heard, and say in the accuracy note where it comes from.

## Accuracy and wording rules

These come from how the Mystery series is written and carry over unchanged in spirit.

- List what is verified and what is illustrative, and name the sources. Mark simplified or stylized parts on screen with a small footnote ("Simplified illustration.").
- Do not claim more than the evidence shows. For debated questions, describe the finding and stop there.
- Cartoon characters, settings and quantities are invented for illustration. The video must not imply a real person, place or brand.
- Do not name or show real products, logos, or interfaces. Use generic shapes.
- Avoid loaded shortcuts that overclaim ("always", "never", "proves", "scientists can't explain") unless the source supports them.
- Add a "Wording rules" list to the file with the specific do-nots for the topic.
- Compare the final narration against the verified list line by line before delivering.

## Ideas mode

When the user asks for ideas, give them as a list. For each idea: a working title, the hook line, the one surprising fact, and an accuracy risk to watch. Prefer everyday questions with one clear surprising fact over broad "how X works" topics, and prefer topics that give a new setting and character (the variation rules). A starter backlog is at the end of `references/market-research.md`; mark any idea you reuse as unverified until you check it. Offer to turn any of them into a full episode file.

## Quick checklist before delivering

- Voice-over word count and duration stated; roughly 95-110 words for 42-50 seconds plus a silent end card.
- Scene durations add up and match the voice-over beats.
- Facts verified with named sources; simplified parts labeled; wording rules written.
- One bold moment, named; the rest calm.
- Series constants unchanged; "Variation vs previous episode" filled in and honest.
- Layer Map and Camera Plan present; no more than about 8 layers per scene and 3 blurred layers at once.
- Key content inside the mobile safe area.
- "Full voice-over" block is clean and paste-ready for ElevenLabs.
- Remotion note includes the data-file tip and the performance tips.
- File saved with the naming pattern and presented; chat summary is short.
